STAGE A

Foundation

week 1–3
Getting data in and out
A1 15 min tap ▸
Input Data & Output Data
Every workflow starts and ends here — connect to Excel, CSV, or a database on one end, and land clean results on the other.
Input Data → browse to file/table, check "First Row Contains Field Names" Output Data → pick a file type, set Overwrite vs Append Split results into one file per value with a %specialname% placeholder in the output path
A2 10 min tap ▸
Select tool
Rename, retype, reorder, and deselect fields in one place — the tool you'll drop after almost every join or input to keep the data model tidy.
Uncheck a box to drop a field from the stream Click a field name to rename it inline Drag rows to reorder, or right-click → Sort Alphabetical Change Type dropdown to force Double, String, Date, etc.
A3 15 min tap ▸
Filter tool
Basic mode gives quick point-and-click conditions; Custom mode unlocks a full Boolean expression once the logic needs more than one clause.
Basic: [Region] = "West" Custom: [Sales] > 1000 AND [Region] = "West" True and False anchors route both halves of the split downstream — nothing is deleted
Filter tool — one input, two outputs
A4 20 min tap ▸
Formula tool
The single most-used tool in Alteryx — write one expression, add or overwrite a field, using the same editor across dozens of other tools.
IF [Score] >= 60 THEN "Pass" ELSE "Fail" ENDIF IIF([Region]="West", [Sales]*1.1, [Sales]) Output field can overwrite an existing column or create a new one
A5 10 min tap ▸
Sort tool
Order rows ascending or descending, and stack multiple sort fields for tie-breaking — exactly like a multi-column sort in a spreadsheet.
Add [Region] Ascending, then [Sales] Descending Sort order in the tool = tie-break priority, top field wins first Sorting upstream of a Multi-Row Formula or Unique tool changes their results
Seeing what you built
A6 10 min tap ▸
Browse tool & Results window
Drop a Browse tool, or Ctrl-drag onto a connection, to inspect data at any point — profile fields, check counts, and catch type mismatches before they cascade downstream.
Browse output = data grid + a Profile pane (nulls, min/max, unique count) Ctrl+drag a connection line to auto-insert a Browse without rewiring The Results window flags warnings (yellow triangle) even when a workflow "ran" fine
A7 15 min tap ▸
Data Cleansing tool
One tool, one pass — trim whitespace, fix case, remove nulls or unwanted characters across every field you tick, instead of writing a Formula for each.
Check "Trim Whitespace" and "Remove Unwanted Characters" → Punctuation Toggle "Replace Nulls" separately for String vs Numeric fields Applies to every field selected in the field list in one pass
Data foundations
A8 10 min tap ▸
Field Types (String, Int, Double, Date)
Alteryx enforces a strict type system underneath every tool — a "5" stored as a String won't sort or sum like a Double, and a date stored as text won't work with DateTime functions until it's cast correctly.
V_String vs String — V_ types hold variable length, fixed types are padded Int16 / Int32 / Int64 vs Double — pick Double the moment decimals are possible Select tool → the Type column is where you force "03/14/2026" text into a real Date
A9 10 min tap ▸
Null vs Blank values
A Null means "no value was ever stored"; a blank string "" is an actual, empty value — mixing the two up breaks ISNULL() checks and lets bad rows slide past a Filter that was supposed to catch them.
ISNULL([Field]) catches true Nulls — it returns False for "" IIF([Field]="", "N/A", [Field]) is what actually catches a blank string Data Cleansing → "Replace Nulls" only fires on true Nulls, not on empty text
How Alteryx actually runs
A10 10 min tap ▸
Workflow execution order
Alteryx doesn't run tools strictly left-to-right by canvas position — unconnected branches can run in parallel or in any order, which matters the moment one branch genuinely depends on another finishing first.
Multiple unconnected branches can execute in any order, even simultaneously A tool only fires once every one of its upstream inputs has delivered data Block Until Done (Expert level) is the fix once order genuinely matters
A11 15 min tap ▸
Basic troubleshooting (warnings vs errors)
A yellow warning triangle means the workflow still ran — often with a nulled field or a conversion issue hiding in it — while a red error stops it outright; reading the Results window catches problems before they reach a report.
Yellow triangle = ran with issues (e.g. "field truncated", conversion errors on N rows) Red X = workflow did not complete — the message names the failing tool number Double-click a message in the Results window to jump straight to the tool that raised it

STAGE B

Intermediate

week 4–5
🔒Locked — unlock after finishing Foundation
Combining and reshaping data
B1 25 min tap ▸
Join tool
Matches two streams on one or more fields and gives you three outputs at once — the unmatched Left, the matched Join, and the unmatched Right — so you see exactly what didn't line up.
Configure join fields, e.g. [CustomerID] = [CustomerID] L = left records with no match J = matched records (duplicate field names get a Right_ prefix) R = right records with no match — always check L and R first
Join tool — three outputs
B2 20 min tap ▸
Summarize tool
The GROUP BY of Alteryx — pick group fields, then stack as many aggregations (Sum, Count, Avg, Min/Max, Concatenate) as the report needs, all in one tool.
Group By: [Region], [Product] Sum: [Sales] → Sum_Sales Count: [OrderID] → Count_Orders Concatenate: [SKU] with a comma delimiter — turns rows into one string per group
B3 15 min tap ▸
Union tool
Stacks two or more streams into one — configure by Field Name (safest) or by Position, and Alteryx will warn you about fields that don't line up.
Configuration → "By Name" auto-matches columns regardless of order "By Position" just lines up column order — risky across different sources Great for combining multiple months or regions of the same file layout
B4 15 min tap ▸
Text to Columns tool
Splits one delimited field into several — or into rows — the fast fix for a column that's really three columns crammed together with commas or pipes.
Delimiters: comma, space, or a custom character "Split to Columns" needs a fixed number of results "Split to Rows" handles variable-length lists like "Red,Blue,Green" vs "Red"
Organizing the canvas
B5 10 min tap ▸
Containers & annotations
A workflow with fifteen tools and no labels is unreadable a month later — Tool Containers group and collapse related steps, and annotations explain the "why" a default tool name never will.
Drag a Tool Container from the palette, rename it "Step 2 — Clean addresses" Right-click → collapse to shrink a finished section visually Select a tool → press F2 to leave an annotation that survives a handoff
B6 15 min tap ▸
DateTime tool & date functions
Date math trips up more workflows than almost anything else — DateTimeDiff, DateTimeAdd, and the DateTime tool's parsing options keep formats consistent instead of silently turning into strings.
DateTimeDiff([ShipDate],[OrderDate],"days") DateTimeAdd([OrderDate], 30, "days") DateTime tool → convert "03/14/2026" to Alteryx's ISO format with a custom input pattern
More prep & reshaping tools
B7 10 min tap ▸
Auto Field
Scans every field and resizes it to the smallest data type and length that still fits the actual data — handy right after a Union or database read leaves everything as an oversized generic String.
Drop it right after Input Data or a messy Union Converts "0001234" stored as String(255) down to a right-sized Int32 automatically Re-run it if upstream data changes — sizes lock in at design time, not at runtime
B8 10 min tap ▸
Unique tool
Splits records into two anchors — Unique (first occurrence per key) and Duplicates (everything after) — so you can inspect exactly what's being dropped instead of silently losing rows.
Check only the fields that should define a "duplicate" — usually a subset, not every column U anchor = first-seen unique rows; D anchor = every repeat after the first Route D downstream to a Browse before assuming duplicates are safe to discard
B9 10 min tap ▸
Sample tool
Grabs a subset of rows — First N, Last N, a random %, or 1-in-N skip — for fast iteration while building, instead of running the full dataset on every single test.
First N rows → fastest way to build against a small preview Random % → better than First N when logic needs to be tested against varied data Remove or bypass the Sample tool before the final production run
B10 20 min tap ▸
Cross Tab tool
Pivots rows into columns — one row per Month becomes one column per Month — the same shape change a spreadsheet pivot table does, often required before feeding data into a reporting tool.
Group By: [CustomerID] — one output row per customer Change Column Headers: [Month] — each distinct month becomes its own column Values for New Columns: [Sales] — the number that lands in each new cell
B11 15 min tap ▸
Transpose tool
The mirror of Cross Tab — turns columns into rows — needed when a wide spreadsheet-style export has to become tidy long-format data before a Join or Summarize will work cleanly.
Key Fields stay as-is per row, e.g. [CustomerID] Data Fields — every column selected here becomes two new rows: Name and Value A common prep step right before reshaping further with Cross Tab
B12 15 min tap ▸
Find Replace tool
Looks up values from a second stream against a text field and swaps in a replacement — a lookup-table-driven cleanup for things like standardizing "Calif." and "CA" to "California" without a long nested IF.
Append mode adds a new field with the match; Replace overwrites the original Match on Whole Field vs Substring — Substring catches a value anywhere inside the text Feed it a two-column lookup table: Find value, Replace value

STAGE C

Advanced

week 6–8
🔒Locked — unlock after finishing Intermediate
Row-by-row logic
C1 25 min tap ▸
Multi-Row Formula
The only tool that lets a formula see the previous (or next) row — running totals, flagging a change from the prior record, or sequencing IDs.
[Row-1:RunningTotal] + [Sales] → cumulative sum down a sorted stream Set "Group By" so the running total resets per Region Must sort your data first — the tool has no memory of unsorted order
C2 15 min tap ▸
Multi-Field Formula
Apply the same expression to many fields in one tool instead of duplicating a Formula tool ten times — the compact way to trim, uppercase, or null-check a whole block of columns at once.
Select fields: all *_Amount columns IF ISNULL([_CurrentField_]) THEN 0 ELSE [_CurrentField_] ENDIF [_CurrentField_] is the placeholder standing in for whichever field is running
C3 25 min tap ▸
RegEx tool
Three modes in one tool — Parse breaks one field into several, Match returns True/False, Tokenize explodes matches into rows — for patterns a plain Filter or Formula can't express.
Parse: (\d{3})-(\d{4}) → area code + number as two new fields Match: ^[A-Z]{2}\d{4}$ → validate a product code format Replace: strip anything that isn't a digit from a phone field
C4 25 min tap ▸
Fuzzy Match
Matches records that should be the same but aren't identical — "Jon Smith" vs "John Smyth" — by scoring similarity instead of requiring an exact key.
Match Fields → pick a fuzzy method per field: Levenshtein for typos, Soundex for phonetics Set a Match Threshold (e.g. 85) — lower catches more, but risks false positives Review the Match Score column before trusting an auto-merge
Building for reuse
C5 30 min tap ▸
Interface tools & Analytic Apps
Text Box, List Box, and the Action tool turn a fixed workflow into a form someone else can run — pick a region from a dropdown, and the Action tool feeds that choice into a Filter or Input behind the scenes.
Drop a Drop Down interface tool → set its List Values Action tool → "Update Value" → target the Filter tool's basic condition Run as an Analytic App, not a normal workflow, to see the question prompt
C6 30 min tap ▸
Standard Macro
Wraps a reusable chunk of logic — Macro Input and Macro Output tools define where data enters and leaves — so ten workflows can call one tested piece of logic instead of ten copies of it.
Build the logic normally, then swap the real Input/Output for Macro Input/Macro Output File → Save As → .yxmc Insert into any workflow via Insert → Macro
More field & join tools
C7 15 min tap ▸
Dynamic Rename
Renames fields using a rule, a formula, or a second input's first row — essential once field names come from a source that changes header text between runs, like a bank export with a date baked into the header.
Mode: Rename from Right Input — first row of a second stream supplies the new names Mode: Rename with Formula — e.g. strip a trailing "_2026" from every header Placing it before a Union By Name avoids a "columns don't line up" warning
C8 15 min tap ▸
Dynamic Select
Selects or deselects fields by rule — name pattern, type, or position — instead of a fixed checklist, keeping a workflow working when upstream columns get added or removed between runs.
Rule: Field Name contains "_temp" → deselect it automatically Rule: Field Type is Double → keep only numeric fields for a downstream Summarize Re-evaluates every run, unlike a static Select tool's fixed field list
C9 15 min tap ▸
Multi-Field Binning
Buckets several numeric fields into ranges in one pass — Equal Width, Equal Records, or custom breakpoints — the fast way to turn continuous values into categories for a histogram or segmentation report.
Select multiple fields at once, e.g. [Age], [Income] Equal Records mode → each bin gets the same row count, useful for quartiles Output adds a new _Bin field per selected input field
C10 15 min tap ▸
Append Fields
Cross-joins every row of one stream against every row of another — small lookup values like a tax rate or a single constant get attached to every record, with no join key required.
Target: the main data stream; Source: a single-row (or small) lookup stream Row count multiplies — 1,000 rows × 3 source rows = 3,000 output rows Keep the Source input small; this isn't a substitute for a keyed Join
C11 20 min tap ▸
Join Multiple
Joins three or more streams at once on a shared key, instead of chaining several two-way Join tools — a cleaner canvas, and one place to configure every join field.
Add inputs 1, 2, 3... each mapped to the same key field, e.g. [CustomerID] Choose Inner, Full Outer, or Left per input pairing Fewer intermediate L/J/R anchors to manage than stacking multiple Join tools
C12 20 min tap ▸
Spatial basics (optional)
Create Points, Distance, and Spatial Match handle location-based analysis — assigning stores to territories, or finding the nearest warehouse to a customer — without exporting to separate GIS software.
Create Points tool → build a spatial object from [Latitude]/[Longitude] fields Distance tool → compute miles/km between two spatial objects Spatial Match → is Point A inside Polygon B, e.g. "which territory contains this customer?"

Looping and branching
D1 35 min tap ▸
Batch Macro
Runs the same macro logic once per group in a control stream — one file per region, one query per table name — without hand-building a separate workflow for each.
Macro Input has two anchors: one for the control parameter, one for the data Interface Designer → set the control parameter's Action to update a filename or filter value Runs once per distinct value fed into the control input
Batch macro — one run per control value
D2 35 min tap ▸
Iterative Macro
Feeds a macro's own output back into its input and repeats until a stop condition is met — the tool for recursive problems like bill-of-materials explosion or hierarchy flattening.
Macro Output → "Iterate" mode, connected back to Macro Input Set a Loop condition: max iterations, or a field-based stop test Each pass only sees the previous pass's output, not the original raw data
D3 20 min tap ▸
Detour & Detour End
Routes records down one of two paths based on a condition, then reunites them at Detour End — a cleaner branch-and-merge than juggling separate Filter/Union chains for a one-off exception.
Detour tool → set a condition, or connect a control input True path takes the detour route; False skips straight to Detour End Detour End requires matching field structure on both incoming paths
D4 15 min tap ▸
Block Until Done & Runtime settings
Alteryx doesn't guarantee tool execution order by canvas position — Block Until Done forces one branch to fully finish (e.g. a delete-then-load) before a downstream branch starts.
Connect the "must finish first" branch to Block Until Done's input 1 Downstream tools connect after outputs 2/3, firing only once input 1 completes Workflow → Runtime settings also control temp file location and disk-based processing thresholds
D5 30 min tap ▸
Python tool
Drops into a Jupyter-based code cell inside the canvas — install packages, run pandas or scikit-learn logic, and pass a dataframe back out — for the rare step no native tool covers cleanly.
from ayx import Alteryx df = Alteryx.read("#1") df['flag'] = df['sales'] > 1000 Alteryx.write(df, 1)
Deploying and scaling
D6 20 min tap ▸
Alteryx Server & scheduling
Publishing a workflow to Server turns a file on your laptop into a scheduled job, an API, or a form other people can run — without needing Designer installed.
Publish via the Server tab → set a Collection and permissions Schedule → recurring run time, or trigger via the Gallery/API Version history keeps prior published copies if a scheduled run needs rolling back
D7 25 min tap ▸
Performance & the AMP engine
Record-limit switches while building, In-DB tools to push heavy joins and aggregations down to the database, and the AMP (parallel) engine all matter once a workflow stops being "quick to build" and starts being "expensive to run."
Input Data → temporary record limit while designing, remove before the final run In-DB Connect → Data Stream In/Out to push filters/joins to the database engine Options → User Settings → enable the AMP Engine for parallelized execution on large workflows
Handling errors, debugging, and integration
D8 20 min tap ▸
Error handling (Message & Test tools)
The Message tool raises a custom warning or error mid-workflow based on a condition, and the Test tool asserts an expectation about the data — together they turn silent bad data into a loud, catchable failure instead of a wrong report nobody notices.
Message tool → condition [RowCount] = 0 THEN fire an Error, stopping the run Test tool → assert row count is between two bounds, or a field has zero nulls Feed a Filter into Message so only the failing subset raises the alert
D9 20 min tap ▸
Workflow debugging
Real debugging means isolating exactly where a workflow diverges from expectations — disabling downstream tools, dropping temporary Browses at each stage, and comparing row counts step by step.
Right-click a tool → Disable to isolate everything upstream of a suspected break Ctrl+drag a Browse onto any connection to check row counts at that exact point Compare a Summarize (Count) before and after a Join or Filter to see where rows vanished
D10 20 min tap ▸
Memory optimization
Alteryx quietly spills to disk once a workflow exceeds available RAM, turning a "fast" workflow into a crawl — knowing when that happens, and avoiding pulling more data into memory than necessary, keeps large workflows fast.
Options → User Settings → default temp / disk-based processing threshold Filter and Select as early as possible — drop rows and fields before a Join, not after Sort and Join are the most memory-hungry tools; sequence them after the data's already trimmed
D11 25 min tap ▸
API integration
The Download tool calls a REST API directly from the canvas — pulling live data or pushing results out — and a published Server workflow can itself become a callable API endpoint for other systems to trigger.
Download tool → set the URL (can be dynamic, from a field), Method, and Headers per row Parse a JSON response with the JSON Parse tool into normal Alteryx fields Publish to Gallery as a workflow app, then call its Server API endpoint from another system

Naming & layout

Rename tools past their default label — "Formula (7)" tells a reviewer nothing six months later.

Debugging habit

Check the L and R anchors on every Join before trusting the J output — most "missing data" bugs live there.

Before you save
