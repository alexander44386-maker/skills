Custom number formats
A cell showing "45000" and a cell showing "$45,000.00" can hold the exact same underlying number — formatting is a display layer, not a data change. Learning a few custom format codes means you never have to retype a number as text just to make it readable, which quietly protects every SUM and AVERAGE that touches it.

Flash Fill

Flash Fill watches the pattern in an example you type once, then fills the rest of the column to match — no formula required for a one-off cleanup.

Formulas
B4 ✓ mastered 25–30 min tap ▸
INDEX + MATCH combo
XLOOKUP is easier to write, but INDEX+MATCH is still everywhere in older files and job tests, and it does one thing XLOOKUP can't as cleanly: look up a value using two criteria at once (row and column) by nesting a second MATCH inside INDEX. Understanding how the two functions split the work — MATCH finds the position, INDEX returns what's there — also makes XLOOKUP's internals make sense.
=INDEX(C:C, MATCH(E2, A:A, 0)) MATCH(E2, A:A, 0) → finds which row E2 lives in (0 = exact match) INDEX(C:C, that row) → returns column C's value from that row Two-way version, row AND column lookup: =INDEX(B2:F20, MATCH(row_val,A2:A20,0), MATCH(col_val,B1:F1,0))
MATCH finds the position, INDEX returns the value

Data Validation lists
Free-text entry is where shared sheets go to die — "West", "west", " West" and "W" all mean the same thing to a human and four different things to SUMIFS. A dropdown list forces every entry to match one of a fixed set of values, so your lookups and totals stay reliable even when five different people are editing the file.

B6 ✓ mastered 20 min tap ▸
Text functions: TEXTSPLIT, TRIM, LEFT/RIGHT
Exports from other systems are rarely clean — extra spaces, "Last, First" formatting, inconsistent casing. Fixing this by hand doesn't scale past a few dozen rows, and it's a mistake to just eyeball it: two names that look identical can differ by a trailing space and break every lookup that depends on them. These functions turn a five-minute manual cleanup into a formula you write once.
=TRIM(A2) strips leading/trailing/double spaces =TEXTSPLIT(A2," ") splits "Jane Doe" into two spill cells =LEFT(A2,3) / =RIGHT(A2,4) grabs fixed-length substrings =PROPER(TRIM(A2)) combine functions: clean casing + spacing together

PivotTables, properly
A basic Pivot just sums a column. The real skill is calculated fields (metrics that don't exist in your raw data, like margin %), grouping dates into months or quarters instead of showing every single day, and using slicers so anyone can filter the view without touching a formula. This is what turns a Pivot from "a quick count" into the dashboard your team actually checks.
Insert → PivotTable Right-click a date field → Group → Months PivotTable Analyze → Fields, Items & Sets → Calculated Field Insert → Slicer for one-click filtering, no formulas touched
B3 ✓ mastered 20 min tap ▸
Conditional formatting logic
The built-in presets (color scales, top 10%) only look at one cell at a time. A formula-based rule can compare across columns — highlight a whole row when the ship date is later than the due date, for example — which is what makes conditional formatting useful for exception-spotting instead of just decoration.
New Rule → Use a formula to determine which cells to format =$D2<$C2 Applies to: =$A$2:$D$100 Note the mixed reference: $D2 keeps the column locked but lets the row shift, so the same rule re-checks every row correctly
B7 ✓ mastered 10–15 min tap ▸
Sparklines
A full chart for every row of a 200-row table is visual noise, but a tiny in-cell trend line per row — last 12 months of sales, say — lets you scan for outliers without leaving the table. Sparklines live inside a single cell, so they sort and filter right along with the row they describe.
Insert → Sparklines → Line (or Column, or Win/Loss) Data Range: the 12 monthly cells. Location Range: the single cell to hold it Sparkline Design tab → High Point / Low Point to flag the extremes Group sparklines first so a formatting change applies to the whole column at once
Workbook structure
B5 ✓ mastered 15 min tap ▸
Tables (Ctrl+T)
A normal range is fixed the moment you type a formula referencing it — add ten rows below and your SUM quietly stops including them. Converting a range to a Table makes it self-expanding: formulas, charts, and Pivots built on the Table automatically pick up new rows, and structured references like Table1[Amount] are self-documenting compared to bare cell ranges.
Select any cell in your data → Ctrl+T → confirm headers =SUM(Table1[Amount]) instead of =SUM(D2:D847) =Table1[@Price]*Table1[@Qty] auto-fills down every new row Rename via Table Design tab so formulas stay readable
B8 ✓ mastered 15 min tap ▸
Freeze Panes & Go To Special
Scrolling through a 5,000-row sheet and losing track of which column is which wastes time and invites mis-keyed entries. Freeze Panes locks header rows or columns in view. Go To Special is the other half of navigating a big sheet fast — it selects only blanks, only formulas, or only visible cells in one shot, instead of hunting for them by eye.
View → Freeze Panes → Freeze Top Row (or select a cell, then Freeze Panes, to lock rows AND columns above/left of it) Home → Find & Select → Go To Special → Blanks — selects every empty cell in the range at once Go To Special → Visible Cells Only — copies just what's shown, skipping hidden/filtered rows Ctrl+G opens Go To directly

Formulas
C2 ✓ mastered 30 min tap ▸
Dynamic arrays: FILTER, SORT, UNIQUE
Before dynamic arrays, getting "just the West region rows" meant a helper column, AutoFilter, or copy-pasting into a new sheet — and redoing it every time the data changed. FILTER, SORT and UNIQUE write that logic once as a live formula: change the source data and the results update on their own, spilling automatically into as many cells as needed with no array-entry shortcuts required.
=FILTER(A2:D100, C2:C100="West") keeps only matching rows =SORT(UNIQUE(B2:B100)) distinct values, alphabetized =FILTER(A2:D100,(C2:C100="West")*(D2:D100>50)) combine two conditions One formula in one cell — the rest of the spill range must stay empty
One formula, spilling into empty cells below it
C3 ✓ mastered 30–40 min tap ▸
LET and LAMBDA
Long formulas that repeat the same sub-calculation three times (like a tax-adjusted total referenced in a discount, a total, and a rounding check) are slow to read and easy to get wrong when you update one copy but not the others. LET lets you name a value once and reuse it inside the same formula. LAMBDA goes further — it lets you package logic into your own function, callable by name, instead of copy-pasting the same formula pattern across a workbook.
=LET(price,B2, qty,C2, discount,0.1, price*qty*(1-discount)) Each name is computed once, then reused — faster and more readable =LAMBDA(price,qty, price*qty*0.9)(B2,C2) Formulas → Name Manager → save the LAMBDA as "DiscountedTotal" Then call it anywhere: =DiscountedTotal(B2,C2)
C5 ✓ mastered 15 min tap ▸
Error handling: IFERROR, IFNA
An unhandled #DIV/0! or #N/A doesn't just look messy — it can silently break every formula downstream that references that cell, including totals and charts. The goal isn't to hide every error everywhere (that can bury real bugs during testing); it's to anticipate the specific, expected failure points — a lookup that might not find a match, a division that might hit zero — and give those a controlled, readable fallback.
=IFERROR(A2/B2, "n/a") catches any error type =IFNA(XLOOKUP(D2,A:A,C:C), "no match") catches #N/A specifically, leaves other errors visible for debugging Wrap the outermost formula, not each inner piece — wrapping every sub-part hides where the real problem is
C7 ✓ mastered 20 min tap ▸
3D references across sheets
Twelve monthly tabs with identical layouts shouldn't mean twelve separate manual totals. A 3D reference sums the same cell across a whole range of sheets in one formula, so the total automatically extends to any sheet that lands inside the referenced range.
=SUM(Jan:Dec!B2) adds cell B2 across every sheet from Jan through Dec, inclusive Sheet order matters — the reference includes every tab physically positioned between Jan and Dec, even ones inserted later, as long as they land in that range Data → Consolidate is the point-and-click alternative when tab layouts don't match exactly
Data analysis
C4 ✓ mastered 25 min tap ▸
Scenario tools: Data Tables, Goal Seek
Manually changing an assumption and re-checking the output — over and over for ten different growth rates — is slow and easy to lose track of. A Data Table runs your model against a whole list of assumptions in one pass and lays out every result in a grid. Goal Seek works backward: instead of asking "what happens if growth is 5%?" it answers "what growth rate do I need to hit $1M?"
Data → What-If Analysis → Data Table One-variable: list assumptions down a column, formula in the corner cell, set Column Input Cell to the assumption cell in your model Goal Seek: Data → What-If Analysis → Goal Seek Set cell: your output. To value: your target. By changing cell: your input.
C6 ✓ mastered 25 min tap ▸
Chart design that isn't default
Excel's default chart adds gridlines, a legend, drop shadows, and often a second axis you didn't ask for — all fighting for attention with the one number that matters. Good chart design is mostly subtraction: pick the one comparison the chart needs to make (trend over time? one category vs. the rest?), then strip everything that doesn't serve that comparison.
Select data → Insert → Combo Chart, for two different scales at once Right-click a series → Format Data Series → Secondary Axis Chart Design → Add Chart Element → Gridlines → None Delete the legend if a direct data label says the same thing faster
C8 ✓ mastered 30 min tap ▸
Solver
Goal Seek only handles one input driving one output. Real allocation problems usually involve several decision variables and several constraints at once — how many units of each product to make, given limited labor hours and material, to maximize profit. Solver handles that: define an objective, the cells that can change, and the constraints, and it searches for the combination that optimizes the result.
Data → Solver (enable via File → Options → Add-ins → Solver Add-in if missing) Set Objective: the profit cell, Max By Changing Variable Cells: the quantity cells for each product Add Constraint: labor hours used <= labor hours available, quantities >= 0

Power Query
Copy-pasting data from five different exports every week is a chore that quietly eats hours. Power Query lets you point at the sources once, record a sequence of cleaning steps (remove blanks, split a column, merge two tables), and then just hit Refresh next time — the same steps re-run on the new data without you touching a single cell. It's the difference between a one-time cleanup and a repeatable pipeline.
Data → Get Data → From File / From Web / From Table Each transformation shows up as a step in the "Applied Steps" pane Right-click any step to edit its settings, or the gear icon to reconfigure Home → Close & Load, then right-click the query → Refresh anytime

Formula auditing tools
In a model built by someone else — or one you wrote six months ago — the fastest way to understand a suspicious number isn't re-deriving it from scratch, it's tracing where it came from. Trace Precedents/Dependents draws arrows to every cell feeding into (or fed by) the selected one; Evaluate Formula steps through a nested formula one calculation at a time. For auditors, this is also how you verify someone else's model without rebuilding it from zero.
Formulas → Trace Precedents / Trace Dependents — draws arrows to related cells Formulas → Evaluate Formula — steps through a nested formula piece by piece Formulas → Watch Window — keeps an eye on a cell's value while you edit elsewhere in the workbook Ctrl+` toggles Show Formulas view for a full-sheet scan
D3 ✓ mastered 30 min tap ▸
Financial modeling standards
A model only you can read isn't really finished — someone else has to be able to open it, trust it, and update an assumption without breaking a formula three tabs away. Color-coding by cell type (input vs. formula vs. cross-sheet link) means an auditor can scan a sheet and instantly know which cells are safe to change and which aren't, without clicking into every cell to check.
Blue font = hard-coded input (the only cells someone should ever edit) Black font = formula (calculated — never type over these) Green font = link to another sheet or workbook Document the key once on a "Read Me" tab so it's not tribal knowledge
Data analysis
D1 ✓ mastered 60+ min tap ▸
Power Pivot + DAX
A regular sheet starts to choke around a few hundred thousand rows, and VLOOKUP-based models between multiple tabs get fragile fast. Power Pivot holds millions of rows in a compressed in-memory model and lets you relate tables the way a database does — Orders to Customers to Products — without one giant merged sheet. DAX measures are calculated on the fly against whatever filter is currently applied (a slicer, a Pivot row), which regular formulas can't do.
Gross Margin % := DIVIDE([Total Revenue]-[Total Cost],[Total Revenue]) DIVIDE returns blank instead of #DIV/0! on a zero denominator Measures recalculate per filter context automatically — the same measure shows a different number for "2026" vs. "West Region" without you writing separate formulas for each
Data Model — related tables, not one giant merged sheet
D4 ✓ mastered 40 min tap ▸
Sensitivity & Monte Carlo sims
A single "our best guess is 8% growth" number hides how much uncertainty is actually baked into a forecast — and it invites someone to treat a guess as a guarantee. Simulating thousands of plausible outcomes and looking at the resulting spread (a histogram, a range of P10/P50/P90 outcomes) is a more honest way to communicate a forecast, and it surfaces which assumptions actually drive the most risk.
=NORM.INV(RAND(), mean, std_dev) Drag this down 1,000+ rows to generate a distribution of outcomes Feed that column into your model's formula, then chart the result as a histogram to see the range of outcomes, not just one point estimate
D8 ✓ mastered 25 min tap ▸
Scenario Manager
Data Tables are great for testing one or two variables against a formula, but a real forecast usually needs to flip between whole sets of assumptions at once — "Best case," "Base case," "Worst case," each changing five inputs together. Scenario Manager saves each named set and lets you switch between them, or generate a summary comparing all of them side by side, without retyping numbers every time.
Data → What-If Analysis → Scenario Manager → Add Name it ("Best Case"), select the changing cells, enter that scenario's values Repeat for each scenario, then Show to switch, or Summary for a side-by-side comparison table Pairs well with Data Tables: Scenario Manager for whole assumption sets, Data Tables for single-variable sweeps

If a task takes ten identical clicks every Monday, that's ten opportunities to fat-finger a step, and ten minutes you're not getting back. Teaching it to someone else
It's possible to build a working formula by trial and error without fully understanding why it works — and that gap usually only shows up when something breaks and you can't debug it, or when a colleague asks "why did you do it this way?" Explaining a model out loud, step by step, forces you to either confirm you understand it or find the exact spot where you don't.
Record a 5-minute walkthrough of your model, narrating as you go Any spot where you say "I think this basically..." — that's the formula to go back and actually study Bonus: have someone unfamiliar with the file try to break it
